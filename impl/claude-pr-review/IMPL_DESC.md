# Owner-authorized Claude PR review

## 1. Title and high-level scope

Provide a static Claude review, paid through the existing `ANTHROPIC_API_KEY`
Actions secret, only after Kayyo321 explicitly requests it. The fixed repository
ID is `1404691070`; the fixed authorizing GitHub user ID is `76451541`.
These IDs were verified against GitHub before implementation. Repository or
account renames preserve these identities; transferring ownership does not
automatically delegate authorization.

Two requests are accepted: Kayyo321 changes a draft PR to ready, or Kayyo321
creates a PR Conversation comment whose complete body is `/claude-review`.
The latter works on existing ready PRs, including other authors' and fork PRs.
An initially ready PR is reviewed only after the command. Another person's
ready event, command, push, PR creation, edit, or review cannot authorize spending.
Draft and closed PRs are rejected. Every new review needs a fresh request;
Actions reruns are rejected even when requested by the owner.

The result is one Conversation comment with findings, necessary questions,
inspection limits, and one of `NEEDS CHANGES`, `QUESTIONS`, `NO BLOCKERS FOUND`,
or `INCOMPLETE`. It is advisory: it does not approve, request changes through
GitHub's formal review API, merge, modify source, or satisfy branch protection.
No host, guest, hypervisor, IPC, or application behavior changes.

## 2. Architecture and inter-component interactions

```text
GitHub event -> job identity/event gate -> trusted default-branch checkout
  -> prepare: GitHub PR metadata + immutable Git objects -> static review input
  -> review: read-only Claude CLI + Anthropic API key -> local result JSON
  -> publish: check current PR identity/state -> GitHub Conversation comment
```

The workflow uses `pull_request_target: ready_for_review` and
`issue_comment: created`. Both execute the workflow from the default branch
(`origin` currently). Checkout explicitly selects that branch, never PR code.
The job gate runs before a runner or secret-bearing step is allocated. Its
concurrency group is job-level so unauthorized events cannot cancel a paid run.
Only a new authorized request can cancel an older request for the same PR.

The Bash controller uses the runner's Git, jq, gh, tar-free blob extraction,
and coreutils. These are CI orchestration tools, not application components or
vendored libraries. All JSON parsing is delegated to the packaged jq utility;
no new native untrusted-input parser is introduced. No submodule is added,
updated, initialized, or executed. Submodule gitlinks are recorded as unavailable
source. The existing checkout action remains pinned to its repository-used SHA
`11bd71901bbe5b1630ceea73d27597364c9af683` (MIT).

Claude Code is an external Anthropic service client, installed into the ephemeral
runner at the exact version `2.1.301`, matching the locally inspected CLI. The
official native installer verifies the downloaded release checksum. No third-party
source is copied into this repository. Upgrades require a reviewed workflow edit.
Claude Code's vendor terms apply independently of the repository's license.

Preparation and publication receive `GH_TOKEN` only. Review receives the
Anthropic key only. The CLI process gets a minimal environment and no GitHub
token, Actions event path, or Actions command-file paths. Restricted mode confines
file tools to the review input directory. Bare mode, disabled slash commands,
an empty MCP configuration, and an explicit Read/Glob/Grep tool list prevent
PR hooks, plugins, MCP servers, shell execution, writes, and network tools.
These controls constrain model tools; they are not an OS sandbox against a
compromised vendor binary. PR text remains untrusted review material.

## 3. Data structures, protocols, and memory layouts

There is no binary ABI, shared memory, alignment requirement, or custom allocator.
Files are process-owned UTF-8 JSON or text in an ephemeral runner directory:

- `request.json`: PR number, head SHA, base SHA, and base ref captured at request
  processing time. SHAs are validated as 40 lowercase hexadecimal characters.
- `metadata.json`: GitHub REST pull request response, retained as data.
- `changes.diff`: three-dot-equivalent merge-base-to-head diff generated by Git
  with external diff and text conversion disabled. Maximum size: 4 MiB.
- `source/`: regular blobs from the exact head tree. Each file is at most 8 MiB;
  the snapshot is at most 64 MiB. Git paths are NUL-delimited, quoted, and checked
  against absolute and parent traversal paths before directory creation. Symlinks
  and gitlinks are never materialized. Git archive attributes cannot hide files.
- `omitted.txt`: paths/modes excluded by the regular-file or size constraints.
  The prompt requires disclosure when missing source limits a conclusion.
- `policy/`: AGENTS.md, PROJECT.md, and CONTRIBUTING.md from the trusted checkout.
  PR copies may be assessed as proposed changes, never treated as tool policy.
- The CLI result JSON lives outside the accessible input root. A successful
  response requires `subtype == "success"`, `is_error == false`, a nonempty
  result, a recognized verdict line, and at most 50,000 UTF-8 bytes.
- `comment.md` is controller-owned output. The controller supplies the reviewed
  head/base SHAs and Actions run URL independently of model claims.

The shell owns its local variables; process exit releases them. No handwritten
heap allocation or pointer ownership crosses a boundary. Runner teardown owns
all temporary files. The GitHub comment is durable. No artifacts, transcripts,
credential files, or PR snapshots are uploaded.

## 4. Step-by-step execution sequence

1. Match the fixed repository/account IDs, actor, original event sender, current
   triggering actor, first run attempt, event type, and exact command or ready
   activity. Repeat these checks in the controller before preparation.
2. Install the pinned Claude CLI without exposing either API credential.
3. Retrieve the live PR. Require open and non-draft state. A ready event must
   still match the head and base recorded in that event; a comment selects the
   live head/base when its job begins. Neither request becomes sticky consent.
4. Fetch the base commit and base repository's PR head ref without recursion.
   Verify the fetched head exactly matches the captured head. Compute the merge
   base and diff; materialize regular head blobs without checkout or execution.
5. Copy trusted project policy and recheck the live PR before API spending.
6. Run a new nonpersistent Sonnet review with a 25-turn limit, CLI budget setting
   of USD 3, a 15-minute review-step timeout, and a 20-minute job timeout.
   The CLI budget is its spending control, not a guaranteed invoice-level cap;
   an in-flight request can finish before a limit is enforced. Anthropic account
   spend limits remain the account-level control. New commands can incur new cost.
7. Independently validate model completion and verdict syntax. On CLI failure,
   empty/invalid output, or exhausted budget/turns, publish `INCOMPLETE` when the
   PR still matches. The failed review step keeps the Actions run failed.
8. Re-fetch the PR immediately before publication. Require the same open,
   non-draft PR, head SHA, base SHA, and target branch. If any changed, publish
   nothing and report the stale request in Actions; the owner must request again.
9. Post one new Conversation comment. No automatic retry of this write occurs,
   because an uncertain network result could otherwise duplicate a comment.

## 5. Concurrency, threading, and synchronization

Each job is sequential; there are no threads, locks, atomics, or memory fences.
Jobs for different PRs are independent. An authorized newer request cancels an
older job for the same PR. GitHub concurrency can replace a pending run; commands
are requests, not a guaranteed FIFO queue. Cancellation skips publication.
Requests do not subscribe to `synchronize`, and reruns do not consume credits.

Metadata checks bracket preparation and publication. GitHub's comment API has no
atomic compare-head-and-comment operation: a push can land in the final interval.
Every comment therefore identifies its exact reviewed head and base. Such a
comment remains advice about those commits, not a statement about newer code.

## 6. Error handling and failure modes

Identity/event mismatch, malformed metadata, draft/closed state, missing objects,
unrelated histories, oversized diff, or fetch/API failures stop preparation before
Claude runs. Errors remain visible in Actions. If preparation succeeds but review
fails, publication attempts an explicit `INCOMPLETE` comment; cancellation and a
stale PR suppress it. Missing secrets, insufficient API credits, unavailable model,
timeouts, or malformed CLI output cannot produce `NO BLOCKERS FOUND`.

Gitlinks, symlinks, oversized source files, unavailable native Windows/GPU runtime,
and static-only test inspection must be disclosed where material. The reviewer
must never claim tests ran. It checks C/Zig/C++ boundaries, ABI/layout, integer
bounds, resource ownership, concurrency, documentation, tests, and implementation
tracker claims against evidence, prioritizing introduced correctness bugs over nits.

Repository administrators can edit workflows/secrets; this policy does not defend
against administrators deliberately changing it. Actions' normal fork approval
settings can add a gate but never replace this workflow's owner authorization.

## 7. Verification and testing criteria

Run `bash tests/ci/claude_pr_review.sh` with Bash, jq, and Git. Fixtures use real
local Git histories and mock gh/claude processes; no network, key, API spending,
or GitHub write is permitted. Cover owner ready and comment requests, strangers,
collaborators, spoofed sender IDs, wrong repository, reruns, edited comments,
ordinary issues, drafts, closed PRs, hostile PR source, source omissions, stale
head/base/target branch, invalid model results, CLI failure, and publication.
Repeat the matrix to stress isolation. The accompanying credential-free
`claude_pr_review_checks.yml` workflow runs these tests and ShellCheck on the
feature branch and on PRs changing this feature; it never receives an API key. Run Bash syntax and ShellCheck on both
scripts and validate workflow structure, triggers, permissions, secret separation,
and the pre-run authorization gate. ASan/LSan and Zig allocator runs do not apply
to shell orchestration; no C/Zig memory or protocol code changes.

A live paid smoke test is deliberately reserved for the owner's first real
request after merge. Do not record live integration as passed before that run.

## 8. Activation and operation

Merge the feature PR into `origin`; comment events need the workflow on the
default branch. Keep the existing repository Actions secret named exactly
`ANTHROPIC_API_KEY`. No Claude GitHub App or personal access token is required.
The workflow grants `contents: read` and `pull-requests: write` to its ephemeral
GitHub token, solely for fetching PR metadata and posting its comment.

For a draft PR, have Kayyo321 click **Ready for review**. If somebody else does
that, Kayyo321 can subsequently post `/claude-review` in Conversation. For a PR
already ready, post that same exact comment. Inline review comments, comment
edits, extra arguments, and command substrings are not accepted. After new commits,
post a new command. Check **Actions -> Claude PR review** for failures. Do not make
this opt-in workflow a required check for all PRs.
