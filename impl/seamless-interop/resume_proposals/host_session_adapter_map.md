# Host adapter API map for a future `waddle-session` loop

## Existing lifecycle and readiness surface

- `daemon_device_get_socket_path()` in `src/daemon/daemon_device.c:117-138` resolves a per-device AF_UNIX control socket under `$XDG_RUNTIME_DIR/waddle/<device>/daemon.sock` (fallback `/tmp/waddle-<uid>/<device>/daemon.sock`). `daemon_device_get_state_dir()` (`:104-115`) resolves per-device persistent state.
- `daemon_state_init()` and `daemon_state_acquire_lock()` in `src/daemon/daemon_state.c:177-300,303-399` load a named device config and hold a per-device OFD write-lock for the daemon lifetime. The lock record is mode 0600, same-user-owned regular file (`:314-343`). The daemon runtime directory is created/verified as same-user-owned and private (`:236-238`, `ensure_dir` at `:161-175`).
- Control APIs are `waddle_client_ensure_daemon()`, `waddle_client_status()`, and `waddle_client_start()` in `src/daemon/daemon_client.h` (declarations near lines 67-130), implemented in `src/daemon/daemon_client.c`. `daemon_server.c:45-59,104-108` dispatches start/status to `daemon_state_start_subsystem()` / `daemon_state_get_status()`.
- There is no `GuestReady` state/API. The wire enum `waddle_subsystem_state_t` has Stopped, StartingVirtiofs, StartingQemu, WaitingGuest, Running, Stopping, Failed (`include/waddle/daemon_protocol.h:108-123`). Status returns state, QEMU PID, only the legacy first virtiofsd PID, VSOCK CID/port, and mount configuration (`daemon_state_get_status`, `src/daemon/daemon_state.c:752-777`). When start uses `DaemonStartFlagWaitGuest`, its “guest ready” probe is just a successful VSOCK `connect()` to the configured CID/port (`:641-674`); it does not run protocol-v2 Hello/mapping validation. `Running` therefore means the daemon's current start/readiness condition succeeded, not that an interop session reached handshake `Ready`.

## Backing, mounts, and ownership

- The daemon owns mounts via `daemon_state_t` (`src/daemon/daemon_state.h:27-79`): one `virtiofs_process_t` plus seven additional process records, a contiguous owned prefix, captured mount-identity snapshots, and per-index socket/log paths. Start preflights all configured roots and drives before child creation, starts one `daemon_fs_spawn_for_mount()` per mount in config order, then passes matching `{socket_path, guest_drive}` entries to `qemu_spawn_for_device_mounts()` (`daemon_state.c:443-554,580-602`). `daemon_fs_stop()/cleanup()` and QEMU stop/kill APIs own process/socket teardown; state shutdown does QEMU first, then mounts, and only then frees AV backing (`daemon_state.c:134-158,731-749`). Keep this lifecycle in the daemon rather than duplicating it in a session adapter.
- AV ownership is `av_environment_t` in `src/av/av_environment.h:10-17`, prepared by `av_environment_prepare()` before QEMU and retained until QEMU/workers are stopped. `src/av/av_environment.c:122-160` supports a newly created private regular backing file (`O_EXCL`, mode 0600; preexisting files are preserved) or `/dev/kvmfr*` character device. KVMFR gets a nonblocking exclusive `flock`, exact 2 GiB size/type checks, existing layout/slot checks, and then a shared read/write mapping; regular backing is sized and mapped similarly (`:135-176`). `av_environment_free()` unmaps/closes and unlinks only a created file whose inode still matches (`:24-41`). QEMU arguments point `memory-backend-file` at `config->av_shm_path` and add `ivshmem-plain` (`src/daemon/daemon_qemu.c:390-410`); the QEMU process record owns its process, QMP/log descriptors, and socket path (`src/daemon/daemon_qemu.h:47-62`).
- Device-scoped exclusivity is split: daemon runtime OFD lock above; AV CLI operations use a separate per-device `state_dir/av/command.lock` flock (`src/cli/av_managed.inc:371-392`). The AV environment itself adds a lock only for KVMFR; normal file backing exclusivity currently relies on `O_CREAT|O_EXCL` plus one daemon owning the device. A new session loop must not invent a second independent AV lifetime or release the daemon mapping.
- On Windows guest, existing signed-driver mapping is `av_ivshmem_init()/av_ivshmem_free()` (`src/av/av_ivshmem.h:8-25`, implementation `src/av/av_ivshmem.c:6-67`). It enumerates an IVSHMEM device, requests the cached mapping, checks size/alignment/layout and retains the device handle for mapping lifetime. It is a guest API, not usable by the Linux host session adapter.

## Transport and local-socket boundary

- Host CLI `connect_peer()` in `src/cli/host.c:198-278` creates `SOCK_STREAM|SOCK_NONBLOCK|SOCK_CLOEXEC`, connects either to AF_VSOCK `{cid,port}` or an explicit AF_UNIX test socket, and completes EINPROGRESS with `poll(POLLOUT)` plus `getsockopt(SO_ERROR)`. The normal process loop then calls `waddle_session()` (`host.c:578-595`). `waddle_session()` (`src/cli/session.c:26+`, declaration `src/cli/session.h:15-36`) is the existing legacy command/stdin/stdout protocol loop, not the new Hello/Ack loop; its framing/queues must not be reused as if they implement interop.
- Guest `guest_listener.c:77-113` binds/listens on configured VSOCK or optional AF_UNIX path and accepts sessions. Existing AV uses a separate VSOCK control port (`src/av/av_host.c:155-176`).
- There is no `SO_PEERCRED`/`SO_PASSCRED` check in the current control or session sockets. The daemon control socket is protected by the private per-user runtime directory plus `chmod(...,0700)` (`src/daemon/daemon_server.c:180-212`); this is filesystem access control, not peer-credential verification. `connect_peer()`'s AF_UNIX path is explicitly a mock/test transport and performs no credential check. VSOCK connect targets a configured guest CID but does not authenticate a guest identity at the OS layer. Keep any new local test socket private and state clearly that protocol connection tokens/correlation are not OS peer authentication.

## Recommended bounded adapter boundary

Add a separate host adapter (for example `src/interop/host_session_adapter.c/.h`) rather than changing legacy `src/cli/session.c`, `src/av/av_host.c`, or daemon lifecycle internals. It should receive an already-owned connected fd plus the selected device's CID/port and a caller-owned validated mapping view/epoch; drive the existing interop reader, send queue, handshake, and liveness value cores from one `poll()` event loop; and report an interop `Ready` result distinctly from daemon `SubsystemStateRunning`. It should not create QEMU, start/stop virtiofsd, map/unmap IVSHMEM, allocate global request IDs, claim producer-stop/detach proof, or signal `FrameRelease` from transport teardown.

A small CLI boundary can use the selected `device_info_t` and `waddle_client_ensure_daemon/status/start` before connecting, but should treat status/start only as VM lifecycle operations. For an actual host-side handshake, connect to `{device.vsock_cid, device.vsock_port}` with the existing nonblocking-connect pattern and keep fd closure under the adapter's owner. If an AF_UNIX test transport is retained, enforce private directory/socket permissions at creation and document that current legacy path has no peer-credential check; do not describe it as authenticated. Cleanup order should be: stop adapter I/O, invalidate its connection token, release only adapter-owned frame/decoder allocations and fd, then leave daemon/QEMU/mount/AV teardown to the existing daemon owner.
