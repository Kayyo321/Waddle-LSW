# TODO #9 path translation and canonicalization proposal

## Current boundary and gap

`src/common/path_rules.zig` is a pure lexical translator. It validates UTF-8 and Windows target syntax, matches a POSIX source by component boundary, drops empty/`.` suffix components, rejects `..` and Windows-invalid suffix bytes, and has no filesystem access. `src/common/arguments.c:waddle_translate_rules()` selects the longest raw source string, keeps relative and non-POSIX strings unchanged, and maps absolute paths with zero rules to the legacy `Z:\` root. `src/daemon/daemon_fs.c:daemon_fs_translate_path()` adds the TODO #9 policy that zero configured mounts cannot map an absolute path, but otherwise delegates to the lexical translator. It does not verify roots or resolve input symlinks. `daemon_fs_spawn_for_mount()` only `stat()`s the raw shared root and passes that spelling to virtiofsd.

The raw-prefix contract already has component boundaries and longest-prefix choice, but it can map a symlink under a share to a target outside that share. Config permits syntactically valid but noncanonical roots and duplicate roots; equal-length duplicate rules are first-wins. CLI `waddle exec --translate-path` (`src/cli/host.c`) loads raw config roots, translates every argv item and cwd lexically, and reports all translation failures as local exit 125. Nonabsolute strings, including Windows drive/UNC paths, pass through. The frozen `waddle open` rule at IMPL_DESC §3.9.1 requires `realpath` for existing host paths and exit 126 for paths outside all shares. The §8.2 #9 contract requires canonical longest component-prefix matching, no implicit root, and zero mounts means no host path is shared.

## Recommended policy

1. Keep `waddle_path_rule_apply()` and `waddle_translate_rules()` as allocation-free/lexical primitives. Add one C filesystem-aware wrapper in `arguments.c`/`path_rules.h` that canonicalizes export roots and POSIX path input before calling the existing lexical mapper. Use that wrapper at CLI and daemon translation boundaries. Do not add `realpath` or filesystem calls to Zig.
2. Export roots must be existing directories. Resolve each root once with `realpath`; reject a symlink in any root component with `ELOOP` rather than accepting a root whose target can be retargeted while a VM is alive. `daemon_fs_spawn_for_mount()` receives the canonical root spelling, and CLI/daemon rules use the same canonical spelling. A symlinked root is therefore configured by its actual target path. This is fail-closed and avoids translation drifting to a different target after the virtiofsd process has opened the export. Missing roots return `ENOENT`, non-directories `ENOTDIR`, permission errors propagate. Root checks happen before launching any backend.
3. For an existing absolute POSIX input, call `realpath`. Match that resolved path against the canonical roots. A symlink that resolves outside all roots is unmapped and rejected; one that resolves inside a configured root maps to the canonical target path. This follows §3.9.1 and prevents lexical in-share aliases from escaping the canonical export boundary.
4. For a non-existing absolute input (needed by commands such as `mkdir`/`touch`), walk upward to the deepest existing ancestor, resolve that ancestor with `realpath`, and append only the genuinely missing suffix components. Reject `..` anywhere before walking; normalize repeated `/` and `.` as the current mapper does. Do not treat an existing broken symlink as a missing component: `lstat` distinguishes it and its `realpath` error is returned. Once the first component is absent, descendants cannot contain a currently reachable symlink. Match the resulting canonical spelling against roots. A missing parent beneath an in-root ancestor remains translatable; an existing symlink ancestor that resolves outside does not.
5. Canonicalize all roots before matching. Continue longest canonical component-prefix matching, allowing nested exports. Reject duplicate canonical roots with `EINVAL` rather than leaving an equal-length first-wins ambiguity. Explicit `/` remains valid and deliberately shares the entire filesystem; it is only used when configured. With zero mounts, absolute POSIX input is unmapped, while relative and guest-native Windows strings remain pass-through.
6. Preserve guest-native paths exactly: strings not beginning with `/` (including `C:\...`, `C:/...`, and UNC spellings) are not passed through POSIX `realpath` and are returned unchanged. Do not reinterpret Windows `..` or separators in this host-path translation layer. The existing Zig target validator remains responsible for mapped target paths.

## Error and CLI behavior

- Invalid input syntax or `..`: `EINVAL`.
- Absolute path outside all canonical exports: use `EXDEV` internally so callers can distinguish an unshared path from malformed input; legacy lexical APIs retain their current `EINVAL` behavior.
- Missing/non-directory/permission-denied configured roots: propagate `ENOENT`, `ENOTDIR`, or `EACCES`; do not start any virtiofsd process.
- Broken input symlink: propagate `ENOENT`; loop: `ELOOP`; overlong canonical result: `ENAMETOOLONG`/existing capacity error.
- `waddle exec --translate-path` keeps its current local-error exit 125 and stderr reporting for translation errors. The frozen `waddle open` contract maps only outside-share `EXDEV` to exit 126 and its existing notification; malformed and local filesystem errors remain local failures (125). Neither path launches a guest command after translation failure.

## Small implementation slice and regression coverage

Add a filesystem-aware helper that owns temporary canonical strings and frees every one on every error; keep its return allocation ownership aligned with the existing `char *` translation API. Make mount validation produce canonical roots before any child spawn, and pass the canonical root to virtiofsd. Reuse the helper in `daemon_fs_translate_path()` and `waddle exec --translate-path`; leave the legacy no-rules convenience wrapper unchanged for compatibility. Reject canonical duplicate roots during config/rule validation.

Tests should use a private temporary tree with: a real root, nested root, root symlink (rejected), in-root file symlink (maps to resolved target), symlink to an outside directory (unmapped), broken symlink (ENOENT), loop (ELOOP), existing file, missing leaf and multiple missing descendants (map when their deepest existing ancestor is in a root), missing root (ENOENT), duplicate roots including symlink aliases, explicit `/`, zero mounts, component-prefix sibling, `..`, UTF-8, relative input, drive-letter and UNC pass-through. Assert both mapped results and errno. CLI tests should assert exit 125 for `exec` translation failures and the §3.9.1 exit-126 behavior at the `waddle open` boundary. No test should require a VM or virtiofsd process.
