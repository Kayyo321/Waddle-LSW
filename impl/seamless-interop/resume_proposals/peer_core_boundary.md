# Proposed peer-core and C/OS adapter boundary

## Scope and ownership split

Add one allocation-owning Zig peer object (suggested `src/interop/peer_core.zig`) behind a small opaque C ABI header. It composes `stream_reader.reader_t`, `stream_send_queue.queue_t`, `session_handshake.session_handshake_t`, and `session_liveness.session_liveness_t`. The object owns the reader's fixed `InteropMaxFrameBytes` accumulator, the queue's copied frames, handshake/liveness values, a bounded writer scratch frame, and copied local-version bytes. It owns no socket, mapping, timer, AV/daemon handle, guest window, or drain proof. C platform loops own the connected fd/socket and monotonic clock; POSIX uses AF_VSOCK and `poll`, while Win32 uses its Viosock socket API and `WSAPoll`/equivalent. Both call the same C ABI and observe copied scalar events.

Do not reuse `src/cli/session.c`'s stdin/stdout transport loop or its legacy wire framing. Host connects to the selected guest CID at frozen port `InteropControlPort` (5002); guest accepts on that VSOCK port. AF_UNIX `session.sock` and local-only 0x7Fxx message types are a separate local adapter/security boundary, not accepted by this VSOCK peer object.

## Codec and borrowed-memory rules

The C codec in `include/waddle/interop_protocol.h` provides `interop_header_decode`, `interop_payload_validate`, `interop_field_get`, typed `interop_field_uint`/other field readers, and `interop_writer_init` / `interop_put_bytes` / `interop_put_uint` / `interop_writer_finish`. It performs allocation-free structural, ordering, padding, direction and schema validation. Writer finish writes the header only after payload validation. It intentionally does not enforce request-ID, outstanding-response, capability-negotiation, or connection policy.

`stream_reader.reader_t` accumulates at most one complete frame and its `peek()` returns frame/payload slices into its own storage; those slices expire when the reader is consumed/mutated. The adapter must validate `payload_validation == InteropErrorNone` before interpreting fields. For a control message, parse fields synchronously into copied scalar facts before `consume()`. For every other valid message, either invoke a synchronous callback before consuming (callback must not retain any view) or copy the entire frame into a caller-provided output buffer and return its exact length. Prefer the copy-out ABI so a C/Win32 caller cannot accidentally keep a dangling slice. If output capacity is short, leave the complete input frame pending and report required length; do not consume it.

The outbound queue copies the complete encoded frame and owns that copy until full write acknowledgement or deinit. A `peek_tx` pointer may borrow the current front only until `ack_tx` or any queue mutation; alternatively expose copy-out. The OS loop calls ack only with a successful send byte count. Compare against the front remainder and call the handshake's `hello_sent`/`ack_sent` only when that frame is fully acknowledged; queueing or a partial send never grants Ready. On terminal teardown, stop I/O first, invalidate the local callback token, then destroy the core (deinit queue and records); the outer session owner separately drains/releases facilities and unmaps resources. EOF, timeout, Error or Goodbye alone is never proof that shared-memory producers/stores are detached.

## Frozen control fields and correlation

The message table is frozen at `impl/seamless-interop/IMPL_DESC.md:521-533`; the codec uses critical base tags with the high critical bit on wire. Writer calls use base tags in ascending order:

| Message | Type and direction | Required fields (base tag / type) | Request ID policy supported by frozen text |
|---|---|---|---|
| Hello | `0x0001`, Guest→Host | Capabilities `0x003A/u64`, AgentVersion `0x003B/UTF-8`, LayoutVersion `0x003C/u32`, SessionEpoch `0x003D/u64`; optional Message `0x0039/UTF-8` sorts before them | Guest allocates nonzero ID; Host HelloAck echoes it (explicit §8.14 endpoint policy). |
| HelloAck | `0x0002`, Host→Guest | Capabilities, AgentVersion, LayoutVersion in tag order | Response: echoes Hello ID; it contains no epoch. |
| Goodbye | `0x0003`, either direction | Status `0x0038/u32`; optional Message `0x0039/UTF-8` | Message table gives no response pair; whether it must use request ID zero or a nonzero request ID is not explicit. |
| Ping | `0x0004`, Host→Guest | no payload fields | Host allocates nonzero request ID; Guest Pong echoes it. |
| Pong | `0x0005`, Guest→Host | no payload fields | Response echoes Ping ID; adapter enforces nonzero, unlike the structural codec. |
| Error | `0x0006`, either direction | optional Message `0x0039/UTF-8`, required ErrorCode `0x0046/u32`, optional RefusedType `0x0047/u16` in ascending-tag order | General header rule says responses echo request IDs, but the table has no per-error correlation policy. Core must never reply to a received Error. |

Header `request_id` is zero for unsolicited messages; response IDs echo the corresponding request. Request IDs are allocated by sender from that direction's sequence starting at 1, incrementing and wrapping `0xFFFFFFFF` to 1, and cannot be reused while a response is outstanding (`IMPL_DESC.md:290-305`). Header framing and payload validation alone do not enforce this. Hello and Ping IDs belong to their sender's direction; their replies do not allocate an ID. A peer-core must use the same per-direction allocator for Ping and all later request/response modules, not a private Ping counter. Liveness's `ReleasedIds` must be returned to that shared allocator on Pong match, per-Ping expiry, or disconnect.

## Handshake, parsing, event loop

The C ABI should use an opaque `interop_peer_t *`, fixed-width scalar arguments, integer result codes, and a documented event struct; never expose Zig tagged unions or slices directly. Suggested operations are create/destroy, guest mapping-initialized, host mapping-validated, feed bytes, copy next event, enqueue caller frame, peek/copy TX, acknowledge written bytes, tick, and begin drain. All calls on one peer are serialized. Time is caller-supplied monotonic milliseconds; all C callbacks carry the nonzero connection token captured when queued so stale callbacks fail without mutation.

Creation takes role, local capability offer, local configured full agent-version string, connection token and accepted/ready time; core copies the bounded version string. Parse the entire ASCII SemVer 2.0 string (including optional prerelease/build, no prefix or trailing bytes), require the `major.minor.patch` grammar, reject leading zeros where SemVer forbids them, and reject major overflow beyond `u32`. Do not treat malformed as major zero. For outbound Hello/Ack serialize the configured full version string, while the handshake stores/compares only parsed major. For inbound Hello/Ack, use `interop_field_get` on the validated payload, parse its exact non-NUL-terminated bytes, then pass copied `?u32` facts to the handshake. Never retain a payload-field pointer past reader consume.

Host flow: accept a complete Guest Hello; enforce nonzero request ID, protocol/layout/major/capability policy; stage epoch/offer; validate full mapping through the external owner; enqueue HelloAck with capability intersection and echoed Hello ID; call `ack_sent` only on complete write; only then report Ready. Guest flow: after external mapping initialization, reserve one Guest-direction ID and call mapping_initialized; enqueue Hello with copied epoch and full configured version; call `hello_sent` only on complete write; receive the echoed HelloAck, check exact request ID/protocol/layout/major and known subset of the local offer; then report Ready and commit the staged epoch. Do not recompute the intersection on Guest because Ack has no separate Host offer.

Before Ready, feed complete frames only through the handshake/core control dispatcher. In Ready, Ping→Pong is handled internally; Pong is matched/ignored by liveness and releases IDs as directed; other codec-valid frames are surfaced by copy-out to the feature owner, which must enforce negotiated capabilities. On each tick, first apply liveness: host may reserve a shared ID, register Ping before enqueue, then enqueue one Ping; if a required enqueue fails, close. Timer cadence advice is not proof a Ping was sent. Incoming complete valid frames refresh receive timeout. A frame at the exact 6000 ms deadline disconnects before processing; each pending Ping independently expires at its own 6000 ms. No reconnect/backoff loop or UI/socket readiness is part of this object.

## Deferred or unresolved contract decisions for lead

1. **Goodbye request ID and behavior:** the frozen table specifies fields/direction but no response or header-ID rule. Recommend unsolicited `request_id=0`, no reply, deliver status/message to the owner and initiate owner drain. Confirm this policy before implementation. Local outbound Goodbye should be queued before teardown with bounded best-effort send; transport completion is not mapping-detach proof.
2. **Error correlation:** Error is both-direction and may refuse a request, but exact request-ID rules are not in the table. `session_handshake`'s `ErrorAndDrain` action carries only a code, and `mapping_validated` clears the staged request ID on failure. Decide whether the adapter snapshots the triggering header ID / retained pending Hello ID and echoes it, or whether an uncorrelated Error uses zero. Do not answer an inbound Error. Hello/Ack and Ping/Pong pairs are unambiguous.
3. **Shared allocator API and bound:** no common per-direction request allocator exists in inspected source. §8.15 explicitly requires one shared across features and outstanding IDs, while the frozen sequence alone does not bound concurrent outstanding application requests. Choose a caller-owned allocator API and bounded admission/OOM policy before wiring control and feature requests; never reuse an ID on wrap while outstanding.
4. **Disconnect policy for remote Error/Goodbye:** the pure handshake exposes local `begin_drain` and transport loss, but no remote Error/Goodbye event. Decide whether the future peer core adds typed terminal input methods or returns copied events for the owner to drain; do not mislabel a peer Error as socket EOF or infer cleanup from it.
5. **Output/facility policy:** capability intersection is committed by the handshake but the adapter/core needs an explicit rule for frames belonging to unnegotiated facilities. Recommended boundary: codec-valid frames are copied out, and the feature dispatcher rejects unsupported facility use; alternatively add a frozen capability-to-message table first. Never infer that successful handshake alone initializes a surface/audio/clipboard facility.

This proposal defines no new wire fields, no signed-driver/guest acceptance, no daemon GuestReady status, and no host-drained or producer-detach proof.
