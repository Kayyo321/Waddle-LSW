# Guest Windows adapter map for the seamless session agent

## Reusable code and hard separation

**IVSHMEM open/map:** src/av/av_ivshmem.c and av_ivshmem.h already own SetupAPI enumeration, open, cached mapping request and symmetric release. av_ivshmem_init(memory, device_index) enumerates GUID_DEVINTERFACE_IVSHMEM, obtains an interface detail path, calls CreateFileW with GENERIC_READ | GENERIC_WRITE and shared read/write, then DeviceIoControl(IOCTL_IVSHMEM_REQUEST_MMAP) with IVSHMEM_CACHE_CACHED. It retains the driver handle and mapping pointer/length in av_ivshmem_t. av_ivshmem_free issues IOCTL_IVSHMEM_RELEASE_MMAP, clears the mapping pointer, closes the device handle and zeros length; this is the current lifecycle. However, its void API ignores release-IOCTL and CloseHandle failures and clears ownership regardless, so it is not a retryable teardown proof. A v3 owner must define how it retains/reports failed release and close before claiming successful unmap. Do not call UnmapViewOfFile on this driver mapping.

Relevant source ranges: av_ivshmem.c:6-18 (release) and :19-63 (open/map/legacy validation); av_ivshmem.h:9-25 (record and contract). Do not directly reuse av_ivshmem_init for the new protocol as written: after mapping it calls legacy av_layout_validate, which requires the old AV layout ABI. av_layout_init in src/av/av_layout.zig writes layout v1. The seamless agent needs layout v3. The narrow adapter should separate “open/map raw signed-driver BAR” from the legacy v1 validator, then hand the still-owned pointer/length to interop_mapping_initialize (src/interop/interop_mapping_init.h/.c) only after the external owner supplied the exclusive-ownership/quiescence precondition. That initializer requires exactly 2 GiB, x86-64 lock-free atomics, aligned writable memory, a fresh nonzero epoch and proof=1; it writes only [0, 0x4000). It cannot prove the mapping is accessible or that old participants are stopped. Host-side interop_layout.zig parsing remains a separate check and is not a mapping open/unmap primitive.

**VSOCK:** src/guest/guest_listener.c and src/av/av_guest.c independently implement the installed Viosock family query. Both open \\.\Viosock read-only and call DeviceIoControl control code 0x0801300c; they require a returned family in 1..UINT16_MAX. Both use a naturally aligned 12-byte guest address {u16 family, u16 reserved, u32 port, u32 cid}, with native-endian fields and local CID UINT32_MAX. The session listener belongs on frozen InteropControlPort 5002, not the existing AV port 5001 or exec port 5242. The helper is duplicated today; extract/reuse this exact ABI through a small guest VSOCK helper rather than copying a third version.

Relevant source ranges: guest_listener.c:6-32 (Viosock address/family query) and :74-120 (listener lifetime); guest_session.c:55-105 (nonblocking peer-close loop); av_guest.c:313-323 and :351-390 (AV VSOCK/map lifetime). guest_listener.c has a straightforward Winsock startup/bind/listen/accept/close loop, but is the existing exec service at port 5242 by default; it handles each accepted peer serially and has no stop event. av_guest.c is a process-bound, one-accept AV service at 5001. For 5002, keep the persistent listener alive across host probes and reconnects, permit only one active session, and treat the daemon's probe-connect/close-before-Hello behavior in IMPL_DESC §3.4 as a harmless unstarted connection. A second active peer must not initialize or mutate the shared mapping.

**Peer I/O:** src/guest/guest_session.c shows Viosock close notification with WSACreateEvent, WSAEventSelect(FD_CLOSE), WSAEnumNetworkEvents, and WaitForMultipleObjects; its AF_UNIX fallback polls exceptional/readable readiness and peeks without consuming framed data. WSAEventSelect makes the socket nonblocking. The AV guest also uses a message pump (PeekMessageW/DispatchMessageW) and high-resolution waitable timer. These are useful Windows event-loop patterns for combining listener/peer readiness, a stop/logoff handle, session timers and UI events.

Do not reuse guest_wire.c/.h as the interop transport. It implements a different custom 32-byte header, sequence counters, CRC, blocking exact reads, a concurrent send critical section and process-spawn body semantics. The new adapter should feed nonblocking receive chunks to stream_reader.zig, dispatch only complete codec-validated frames to session_handshake.zig, enqueue outbound frames through stream_send_queue.zig, and report send confirmation only when every byte of a complete Hello/Ack has been acknowledged by successful Winsock writes. The handshake core itself has no socket or timer-queue ownership.

## Ownership and teardown boundaries

- The logon agent owns the listener, WSAStartup lifetime, named single-instance mutex (Global\WaddleSessionAgent per IMPL_DESC §2.2), per-connection state/reader/send queue, Viosock peer and the open driver mapping record. The frozen architecture calls for one agent per interactive desktop; this is not the per-process waddle-guest-av.exe service.
- Before each accepted real session sends Hello, join prior capture/audio producers and obtain the external proof that old host buffers are detached; then initialize a fresh nonzero layout-v3 epoch. The pure handshake can stage an epoch but cannot prove this precondition. Do not initialize on listener start or on the host readiness probe.
- On orderly Goodbye, timeout, socket loss or local logoff: stop admitting work, stop and join all mapping writers, release held input/session resources, and return the peer to the listener only after local cleanup. EOF/Goodbye/heartbeat timeout is not host-drained evidence.
- Before mapping reinitialization or release, retain ownership until the host-side QEMU/Wayland owner has completed buffer teardown under the separate AV/session lock contract. A wire close or Closed handshake phase is not that proof. Then release driver mapping with IOCTL_IVSHMEM_RELEASE_MMAP and close its device handle only when the agent is actually exiting or the chosen adapter lifecycle requires it.
- Keep the legacy AV path byte-compatible and mutually exclusive with seamless mode per IMPL_DESC §1.3/§6.10. av_guest_setup.c's install/probe concerns the old AV executable and old layout validator; do not report its success as v3 agent readiness.

## Driver and deployment assumptions

- scripts/av.mk extracts ivshmem.inf, ivshmem.sys, ivshmem.cat and license from pinned Looking Glass B7 host setup artifact after SHA-256 verification (c2415a5a0c405f1d6aa936986bdd4b806c50574b4521747e113c3be2be047b1b). The guest installer is signed-driver package content, not loose source.
- Relevant source ranges: scripts/av.mk:120-129 (pinned artifact extraction); av_guest_setup.c:85-125 (pnputil install and reboot status); av_deploy.c::av_deploy_finish (restart/probe sequencing). av_guest_setup.c::av_guest_setup runs %SystemRoot%\System32\pnputil.exe /add-driver ...\ivshmem.inf /install, requires guest administrator rights, waits up to 120 s, and maps install statuses 3010/1641 to “restart required.” av_deploy.c::av_deploy_finish sequences restart, guest probe and host probe after that result. av_guest_probe opens/maps device index 0, validates the current legacy AV layout, probes Windows build >=20348, audio endpoint and D3D11/WGC. A v3 agent needs a v3-aware mapping readiness probe; old probe result is not proof of v3 mapping support.
- Viosock is assumed preinstalled and exposed as \\.\Viosock; this tree queries its family but contains no corresponding install/deploy flow. Driver absence currently surfaces as family-query failure. The package/VM image must independently guarantee this service before promising agent readiness.
- QEMU config is ivshmem-plain,memdev=waddle_av (see src/daemon/daemon_qemu.c); the guest adapter expects the fixed 2 GiB BAR from layout v3. Mapping device enumeration index 0 is current AV convention, not proof that multiple IVSHMEM devices are unambiguous.

## Existing test seams and remaining native blockers

- tests/vgpu/mapping_windows.c demonstrates SetupAPI/CreateFile/DeviceIoControl/CloseHandle fakes and failure-stage ownership accounting for another IVSHMEM mapper. It is a good model for a raw-map adapter fixture, but tests the Venus mapper, not av_ivshmem.c or v3.
- tests/av/guest_quiescence.c reserves a sparse 2 GiB virtual range and commits only metadata pages while replacing capture functions. It validates legacy AV guest scheduling without a real driver/GPU; it does not prove signed-driver mapping or host/guest session detach.
- tests/interop/mapping_init.c covers the v3 metadata initialization C boundary, but not an actual Windows SetupAPI mapping. session_handshake.zig, stream_reader.zig and stream_send_queue.zig are pure/value-level seams; none owns Winsock.
- tests/av/windows.c and .github/workflows/av_passthrough.yml build/run the native AV guest on Windows; native AV acceptance requires the installed signed IVSHMEM driver, desktop/audio/D3D/WGC and therefore is not a CPU-only seam. The existing Windows guest-exec tests use AF_UNIX for their harness, not the VSOCK family/driver.
- Recommended files: src/guest/guest_ivshmem.c/.h for raw SetupAPI map/release (no v1 layout validation); src/guest/guest_vsock.c/.h for the shared family-query/address ABI and listener/peer readiness; src/guest/session_agent.c for logon, mutex and owner cleanup; and src/guest/session_peer.c/.h for one connection's stream reader, handshake, send queue and send-completion events. Keep Windows socket/driver syscall fakes in tests/interop/session_adapter_windows.c and a native Windows target in a new dedicated build/workflow rule; do not fold this into the legacy per-PID AV executable/test target. The frozen package calls for waddle-guest-session.exe at logon with UIAccess, but scripts/av.mk and the existing deployment bundle build only waddle-guest-av.exe plus the WGC adapter/IVSHMEM package, so the session-agent packaging, UIAccess deployment, Viosock provisioning and v3-ready probe are still blockers. Add injected Winsock/SetupAPI/driver APIs for deterministic ownership/failure fixtures; keep real VSOCK+signed-driver+reconnect and actual compositor release as separate native VM acceptance gates. Exclude all reserved Claude graph/observer paths.
