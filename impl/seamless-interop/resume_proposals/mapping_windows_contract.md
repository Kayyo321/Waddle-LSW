# Proposed raw layout-v3 Win32 IVSHMEM mapping owner

## Evidence and boundary

Use the pinned `submodules/looking_glass/vendor/ivshmem/ivshmem.h` ABI through the existing local wrapper pattern, but keep the new owner under `src/interop/` and independent of `av_ivshmem_t`, `av_layout_validate`, `venus_region_attach`, and AV/vGPU mapping validators. The header defines interface GUID `DF576976-569D-4672-95A0-F57E4EA0B210`, `IVSHMEM_MMAP_CONFIG { UINT8 cacheMode; }`, cache mode `IVSHMEM_CACHE_CACHED == 1`, and `IVSHMEM_MMAP { UINT16 peerID; UINT64 size; PVOID ptr; UINT16 vectors; }`. On the required x64 process ABI, assert `sizeof(IVSHMEM_MMAP_CONFIG)==1`, `sizeof(IVSHMEM_MMAP)==32`, and offsets 0/8/16/24 for peerID/size/ptr/vectors. Assert x64 at compile time; do not silently reinterpret an x86 structure.

The IOCTLs are `CTL_CODE(FILE_DEVICE_UNKNOWN, 0x802, METHOD_BUFFERED, FILE_ANY_ACCESS)` (`0x00222008`) for REQUEST_MMAP and function `0x803` (`0x0022200c`) for RELEASE_MMAP. Request input is exactly one config byte; output capacity is exactly 32 bytes on x64 and successful `bytes_returned` must be exactly 32. Release has null/zero input and null/zero output. The requested BAR must report exactly `0x80000000` bytes, a nonnull 64-byte-aligned base, and a non-overflowing `[base, base+bytes)` address range. Rejecting any malformed successful response still requires RELEASE_MMAP because success acquired the driver map.

This layer owns only the device handle and the raw driver mapping lease. It does not parse or initialize shared-memory contents, establish a session epoch, validate slot descriptors, or prove producer shutdown. A separate layout-v3 validator/initializer owns those operations. It must never call either legacy `av_layout_validate` or vGPU `venus_region_attach`.

## Suggested API and ownership

Add `src/interop/interop_mapping_windows.h/.c` with one noncopyable-by-contract, zero-initializable `interop_mapping_windows_t`. Its stored ownership state should include the device handle, SetupAPI device-info-set handle if cleanup can fail, raw base/byte length, returned peer/vector metadata, `owns_handle`, `owns_mapping`, and a small cleanup-state enum. Keep the raw pointers in the owner until ownership is actually relinquished; never clear them merely because cleanup was attempted. Export `interop_mapping_windows_open(owner, device_index, out_view)` and `interop_mapping_windows_close(owner)` as status-returning functions. `out_view` is zeroed on entry and populated only after all open preflight and SetupAPI temporary cleanup succeeds. It is a borrowed view whose lifetime ends only when the owner successfully releases the mapping. The owner must not be copied while active, shared across threads, or reinitialized while it owns anything.

Require `open` to receive an inactive/zero owner; reject an already-owned record unchanged. On full success, return status `Ok`, retain both device and mapping ownership in the owner, and copy `{base, bytes, peer_id, vectors}` to `out_view`. On a failure that fully unwinds, return the original Win32 error and leave owner zero and `out_view` zero. If cleanup itself fails, return a distinct `CleanupPending` status, preserve the cleanup Win32 error separately from the original open error, and leave every still-owned handle/map recorded so the caller can retry `close`. Never report a clean failure when an owned resource remains.

`close` is retryable and idempotent on a zero owner. The caller may call it only after all local workers that can touch the view have joined and the peer/session owner has established mapping detachment. It first makes the local view unusable (clear any derived layout view), then issues RELEASE_MMAP if and only if `owns_mapping` is true. If release fails, preserve `owns_mapping`, raw base/length, and device handle; do not call `CloseHandle`; return `CleanupPending` with the release error. If release succeeds, clear mapping ownership and raw mapping metadata, then call `CloseHandle`. If `CloseHandle` fails, preserve `owns_handle` and the handle value but keep `owns_mapping=false`, so retry closes only and never issues a duplicate release. On successful handle close clear the handle/ownership flag. If a failed SetupAPI-list destruction left `owns_device_info_set`, close also retries `SetupDiDestroyDeviceInfoList`; retain that handle on failure and clear it only on success. Cleanup components that do not depend on the still-owned mapping may be retried independently, but never close the device while `owns_mapping=true`. A retry after any failure must resume at the retained state. Do not infer release success from EOF, socket close, Goodbye, a closed handshake, heartbeat timeout, or process exit without the explicit owner-level detached/quiescent decision.

Keep the existing `interop_mapping_initialize` `exclusive_owner_proof` as a caller assertion only. The caller must establish that prior guest producers are stopped and prior host buffers are detached before writing the 0x4000-byte metadata prefix for a fresh epoch. A nonzero epoch and that proof do not themselves prove quiescence; EOF is not proof. Similarly, close is forbidden until all users and the peer are detached. Mapping ownership and protocol connection ownership remain separate.

## Open sequence and exact SetupAPI calls

1. Validate `owner` and `out_view` pointers and owner inactivity before side effects; zero `out_view`.
2. Call `SetupDiGetClassDevsW(&GUID_DEVINTERFACE_IVSHMEM, NULL, NULL, DIGCF_PRESENT | DIGCF_DEVICEINTERFACE)`; retain the returned `HDEVINFO` until `SetupDiDestroyDeviceInfoList` succeeds.
3. Initialize `SP_DEVICE_INTERFACE_DATA.cbSize = sizeof(SP_DEVICE_INTERFACE_DATA)` and enumerate the requested zero-based interface index with `SetupDiEnumDeviceInterfaces`.
4. Probe `SetupDiGetDeviceInterfaceDetailW(..., NULL, 0, &needed, NULL)`. Accept only the expected insufficient-buffer sizing result and `needed >= offsetof(SP_DEVICE_INTERFACE_DETAIL_DATA_W, DevicePath) + sizeof(WCHAR)` and `needed <= 65536`. Allocate exactly `needed` bytes with checked allocation. Set detail `cbSize = sizeof(SP_DEVICE_INTERFACE_DETAIL_DATA_W)`, then fetch the full detail.
5. Open the returned path using `CreateFileW(path, GENERIC_READ | GENERIC_WRITE, FILE_SHARE_READ | FILE_SHARE_WRITE, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL)`. Store ownership immediately on success; free the path buffer after `CreateFileW` returns.
6. Send one-byte cached `IVSHMEM_MMAP_CONFIG` to REQUEST_MMAP; provide a zero-initialized 32-byte `IVSHMEM_MMAP` output and a `DWORD bytes_returned`. On `DeviceIoControl == TRUE`, mark `owns_mapping=true` immediately before validating any returned fields. Then require exactly 32 returned bytes, size exactly 2 GiB, nonnull pointer, 64-byte alignment and nonoverflowing range. Preserve peerID/vectors as copied metadata only.
7. Destroy the SetupAPI set and free every temporary allocation on all paths. A failure destroying the set is not silently ignored: preserve the set handle for cleanup retry (the owner may be partially owned even if no map was granted). Only after all temporary cleanup succeeds publish the borrowed `out_view` and return `Ok`.

If REQUEST_MMAP returns FALSE, do not claim mapping ownership; preserve its `GetLastError`, then close the device and destroy/free SetupAPI resources. If the request succeeds but its returned byte count/pointer/size/alignment is invalid, attempt RELEASE_MMAP during rollback. A release failure leaves the map and handle in the owner for explicit retry. A later `CloseHandle` failure similarly retains the handle. Preserve the first operation failure separately from rollback errors so diagnostics do not conceal why open failed.

## Linux API-double and native-Windows fixture plan

For Linux tests, separate the lifecycle decisions from direct Win32 entry points behind a private, fixed ops table (enumerate/open/request/release/close/destroy/free), or compile the same C source against narrow test-only SetupAPI/Win32 shims. Do not add a production “fake” branch or alter the driver ABI. The API double must script each acquisition point, report exact input/output lengths, and count live device sets, detail allocations, device handles, and driver maps. Assert clean-failure zeroing and, for rollback failures, exact retained owner flags/pointers and successful retry.

Cover: invalid/null/active owner arguments before side effects; device-set failure; enumeration failure; sizing API returning malformed/too-small/over-64KiB lengths; allocation failure; detail-fetch failure; CreateFile failure; request IOCTL failure; short/long `bytes_returned`; wrong map size; null/unaligned/overflowing pointer; request success followed by release failure; release success followed by CloseHandle failure; repeated close after each retained state; and exact one-time release/close counts. Check that output remains zero unless open fully succeeds and that the original open error remains available after a cleanup error.

A native-Windows CPU fixture should compile the production translation unit with API doubles substituted around SetupAPI, CreateFileW, DeviceIoControl, CloseHandle and allocator calls, following the style of `tests/vgpu/mapping_windows.c`. It should verify actual Windows SDK `cbSize`/`sizeof` values, the real imported IVSHMEM structure layout, `GetLastError` preservation and x64 compilation. This is not a signed-driver/VM/GPU acceptance test. Actual driver enumeration/mapping and full host-detachment proof remain separate native integration gates.

## Existing seams observed

`src/vgpu/venus_mapping_windows.c` already follows SetupAPI enumeration, a 64 KiB detail bound, `CreateFileW`, cached REQUEST_MMAP, and a macro-substituted Windows fixture in `tests/vgpu/mapping_windows.c`. It currently uses `venus_region_attach` and its `venus_mapping_free` ignores RELEASE_MMAP and CloseHandle failures while zeroing ownership, so it is a reference for call shapes only, not a lifecycle implementation to reuse. `src/av/av_ivshmem.c` uses the pinned driver header and SetupAPI similarly but has legacy AV validation/lifecycle. `src/interop/interop_mapping_init.c` initializes only layout-v3 metadata after caller-supplied exclusivity proof and owns no OS mapping. `src/interop/interop_layout.zig` / `interop_layout_abi.zig` provide the separate layout-v3 validation seam. `tests/av/guest_quiescence.c` demonstrates a test-owned memory region and capture API double; it does not test driver mapping acquisition or release.
