## Intended architecture and implementation boundaries

- Existing per-process AV stays compatible on VSOCK 5001 and its existing
  memory layout. New session mode uses VSOCK 5002 and layout v2. A shared
  per-device command lock must prevent both modes owning IVSHMEM at once.
- Planned `waddle-guest-session.exe` tracks the interactive desktop, assigns
  `(session_epoch, window, generation)` identities, captures windows, injects
  input and owns guest clipboard/catalog integration. The guest initializes
  the 2 GiB mapping with 192 frame descriptors and eight audio rings.
- Planned `waddle-session` owns Wayland surfaces, host input and clipboard,
  PipeWire streams, desktop entries and the local launch socket. Its main
  event loop owns control state; realtime audio consumes SPSC rings.
- Existing AV lease, input, capture, deploy, buffer and audio modules are the
  reuse points. Extraction must preserve the existing AV tests and ABI.
- `waddled` and config parsing will gain readiness, VM-device and peripheral
  support. `waddle open` and integration commands depend on these foundations.
- The integration manifest will own every generated artifact and saved prior
  setting, with journaled updates and deterministic repair/removal.

Only `interop_codec.zig` exists under `src/interop/` today. There is no session
agent/client, layout-v2 allocator, catalog, integration manifest, clipboard
bridge, or `waddle open` implementation in this feature yet. Many mechanisms
in the specification describe future code despite present-tense wording.

## Findings to resolve before extending the foundation

These findings were inspected, not fixed, during the requested research phase.

1. **Decoration event handling is incomplete.** `av_wayland_create()` creates
   a `zxdg_toplevel_decoration_v1` and requests a mode but registers no configure
   listener. The installed protocol XML requires the client to obey the
   effective mode, and permits the compositor to choose another mode. Current
   tests record outgoing requests without delivering that configure event.
   Add event-delivery coverage and implement the negotiated-mode lifecycle
   before considering KDE decoration behavior proven. No compositor crash was
   reproduced in this review.
2. **Layout-v2 header size disagrees with the contract.** The fields in
   `IMPL_DESC.md` section 3.3 occupy 72 bytes before `reserved`, but the array
   is `4096 - 80`. The described struct is therefore 4088 bytes, not 4096,
   under the normal 8-byte ABI alignment. A local layout calculation confirmed
   it. Resolve reserved bytes/offsets and freeze compile-time size, alignment
   and offset assertions before TODO #5; no runtime v2 struct ships yet.
3. **Input and compositor serials are conflated.** Section 3.6.2 requires a
   strictly increasing per-connection input serial; section 4.5 assigns the
   raw Wayland button serial `S` to `InputPointerButton.serial`. These are
   separate namespaces: repeated input and keyboard/motion events cannot use
   the compositor serial as the connection counter. Specify a mapping from
   protocol press serials to valid seat serials for move/resize and popups.
4. **App-key truncation can exceed the wire cap.** Section 3.8.2 truncates
   sanitized AUMIDs to `InteropMaxAppKeyBytes - 2`, then adds a two-byte prefix
   and a nine-byte hash suffix. A long AUMID can produce 209 bytes against the
   codec's 200-byte limit. Reserve suffix space before truncation and test
   long, transformed, collision and multibyte cases before catalog work.
5. **Some lifecycle/CLI contracts need completion.** The design relies on
   `waddle session stop` without defining its command grammar. Modified-file
   protection refers to `repair --force`, while the frozen repair grammar
   omits that flag. The first window update is also described as carrying
   minimum dimensions in the ordinary geometry rect, without a discriminator.
   Define these boundaries before implementing the corresponding tasks.
6. **Naming and interface documentation need an audit.** Examples include
   Zig types `FieldSpec`, `MessageSpec`, `Walker` and `TagSet`, which do not
   satisfy the repository's `snake_case`/`_t` rule, and lowercase compile-time
   registry bindings. Several C ABI comments omit explicit parameter
   directions/nullability. Resolve these before claiming policy compliance;
   coverage percentages do not establish interface completeness.

Any correction affecting a frozen wire, memory, file or configuration contract
must follow the specification's versioning rule and be attributed in TRACKER.
Do not silently change frozen contracts while implementing a dependent task.

## Follow-up fixes authorized on 2026-10-23

- Finding 1: fixed in `2450d22`. The registered decoration listener stages
  modes until surface acknowledgement, and forced server-side mode uses the
  extension's destructor fallback. Normal and sanitizer callback gates pass.
- Finding 2: corrected by layout v3 (SMW3). Header reserved bytes begin at 72;
  exact size 4096, descriptor size 64, 64-byte alignment and every field offset
  are asserted in `include/waddle/interop_memory.h` on Linux and Windows builds.
  The allocator/validator remain pending; the old layout v2 is not reused.
- Finding 3: protocol v2 distinguishes the monotonic input counter from seat
  serials through a bounded host press table. Guest move/resize and menu
  trigger references echo input serials; only the host resolves a live entry
  into a compositor serial. Runtime routing remains part of session work.
- Finding 4: `interop_app_key_from_aumid` reserves the prefix and hash suffix
  before truncating. Tests cover 198/199/4096-byte AUMIDs, non-ASCII bytes,
  independent hash vectors, colliding sanitized stems and unchanged outputs
  on errors. Distinct identities sharing a truncated hash must be rejected by
  the future catalog instead of overwritten.
- Finding 5: `min_size` is its own optional field; current `rect` bounds keep
  their meaning. `waddle session stop` now has a local-only request/result
  contract, explicit ownership/cleanup/timeout behavior and idempotence rules.
  `repair --force` has explicit scope, preserved backups and failure handling.
  CLI implementation remains pending in its existing tasks.
- Finding 6: naming/interface documentation cleanup follows as a separate
  atomic commit; no additional feature progress is claimed.
