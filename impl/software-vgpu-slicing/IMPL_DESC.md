# Implementation Description: Software vGPU Slicing

## 1. Title & High-Level Scope
- **Title**: Software vGPU Slicing for Non-MDEV Hosts
- **Scope**: Provide GPU paravirtualization (GPU-PV/vGPU slicing) for hosts that lack native mediated device (mdev) support. We will achieve this using the **Venus** protocol (Vulkan remoting) across IVSHMEM. In the Windows guest, DXVK/VKD3D will translate DirectX 11/12 workloads to Vulkan, which are then remoted via Venus to the Linux host. The host executes the Vulkan commands and exports the rendered surfaces as DMA-BUFs for zero-copy Wayland compositing.
- **Out of Scope**: Full hardware pass-through (PCIe VFIO), native mdev implementations, CPU-only software rendering fallback.

## 2. Architecture & Inter-Component Interactions
- **Host-Side Renderer (virglrenderer/vkr)**: We will integrate a Venus receiver on the Linux host. It receives Vulkan commands from the guest, executes them on the physical host GPU, and manages the Vulkan state.
- **Guest-Side Drivers**: 
  - **WDDM Render-Only / Compute Driver**: A minimal KMD/UMD that satisfies Windows requirements so the OS and DWM recognize the virtual hardware.
  - **Standalone Vulkan ICD**: Implements the Venus protocol. It intercepts Vulkan calls (including those generated by DXVK/VKD3D) and serializes them into the IVSHMEM ring buffer.
- **Transport Layer**: IVSHMEM shared memory region for Venus command ring buffers, supplemented by VirtIO-Serial/VSOCK for lifecycle and synchronization events.
- **Zero-Copy Presentation Flow**: Guest DX11/12 app -> DXVK translates to Vulkan -> Vulkan ICD serializes via Venus -> IVSHMEM -> Host Venus receiver executes -> Renders to Vulkan Image -> Exports as DMA-BUF -> Waddle-LSW Wayland client imports via `zwp_linux_dmabuf_v1` -> Displays as `wl_subsurface`.

## 3. Data Structures, Protocols & Memory Layouts
- **Venus Ring Buffer**:
  ```c
  struct alignas(64) venus_ring_header_t {
      std::atomic<uint32_t> head;
      std::atomic<uint32_t> tail;
      uint32_t capacity;
      uint32_t flags;
      uint8_t reserved[48];
  };
  ```
- **Serialization Format**: Venus protocol binary wire format.
- **Memory Alignment**: 64-byte cache line alignment strictly enforced for IVSHMEM synchronization primitives to prevent false sharing.

## 4. Step-by-Step Execution Sequence
1. **Initialization**: Host proxy daemon allocates IVSHMEM segment. Guest driver loads, maps IVSHMEM, and registers the Vulkan ICD.
2. **Command Serialization**: The guest application issues draw calls. DXVK translates them to Vulkan. The Vulkan ICD encodes them into the Venus ring buffer and updates the atomic tail pointer.
3. **Execution**: The host Venus receiver polls or is notified of new commands, decodes the Venus protocol, and submits the equivalent Vulkan commands to the host GPU.
4. **Presentation**: The guest submits a frame. The host completes rendering and exports the Vulkan Image as a hardware DMA-BUF. The host Wayland client attaches this DMA-BUF to a `wl_surface` for zero-copy display.

## 5. Concurrency, Threading & Synchronization
- **Lock-Free Queue**: The Venus command ring buffer operates as a lock-free Single-Producer Single-Consumer (SPSC) queue.
- **Atomic Operations**: `std::atomic_thread_fence` with `std::memory_order_release` and `std::memory_order_acquire` ensure cross-boundary memory visibility.
- **Host Threading**: The host receiver uses dedicated threads per guest Venus context to maximize throughput and minimize latency for bare-metal performance.

## 6. Error Handling & Failure Modes
- **Buffer Overflow**: If the Venus ring buffer is full, the guest ICD must block and wait.
- **GPU Hangs/TDR**: Handled gracefully by the host tearing down the Vulkan context and notifying the guest driver to trigger a Windows TDR (Timeout Detection and Recovery).
- **Disconnects**: Clean teardown of Vulkan resources and Wayland surfaces upon unexpected guest VM termination.

## 7. Verification & Testing Criteria
- **Unit Tests**: Verification of Venus ring buffer synchronization logic.
- **Integration Tests**: Running `vkcube` and a basic DX12 application in the guest and verifying zero-copy DMA-BUF compositing on the host.
- **Performance Benchmarks**: End-to-end latency must be comparable to native host rendering. Target 144+ FPS for high-performance workloads (Adobe, gaming).
- **Sanitizers**: All host components must pass AddressSanitizer and LeakSanitizer with zero memory leaks.
