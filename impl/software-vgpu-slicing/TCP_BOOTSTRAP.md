# Actual ISO-VM TCP Receiver Bootstrap Contract

Scope: controlled Windows11 VM acceptance only. TCP replaces the guest/controller shared ring boundary for this test. The Linux controller still owns the existing ring mapping, negotiated guest frontend and isolated real virgl/Venus receiver. Physical IVSHMEM remains a separately delegated integration. CPU staging copies are real RequestRead/Write transfers; no Vulkan API result, feature, GPU identity or presentation completion is synthesized.

Process ownership: an explicit owned bootstrap module is loaded by the controlled DXVK process before Vulkan loader discovery. Its start operation receives an absolute private configuration filename, loads the exact ICD DLL named by the guest-path manifest, creates a callback owner, authenticates and negotiates TCP, then calls venus_icd_bind on that loaded DLL. It retains the ICD HMODULE, socket, buffers and synchronization until stop. One ICD binding and one TCP session exist per process. No network work occurs in DllMain. An alternative lazy vkCreateInstance initializer is broader product work and is excluded from this controlled-bootstrap milestone.

Host ownership: one loopback-only listener on an explicit dynamically allocated port, reached inside SLIRP as10.0.2.2. Each accepted authenticated session owns one normal Linux controller-to-worker mapping/control/frame channel and unreaped worker process identity. Host controller runs venus_guest_init with the existing pinned profile and rejects any capset mismatch before admitting guest Vulkan traffic. A connection never shares the receiver or object namespace of another connection. The listener owns accepted sockets and closes them after calls stop; controller owns native mapping/socket/worker teardown independently.

Private configuration: ASCII JSON with exact schema version1, address10.0.2.2 for the ISO VM or127.0.0.1 for native loopback tests, port1..65535,256-bit random capability token as64 lowercase hexadecimal digits, absolute Windows ICD DLL path and exchange_timeout_ms1..60000. Reject extra/duplicate keys, oversized paths, invalid hexadecimal, embedded NUL, nonabsolute path, unsupported version/address (only those two exact IPv4 literals) and files larger than4096bytes. Generate token per launch with a cryptographic OS RNG; retain private host/guest files and never place credentials/token in argv, logs, tracker or commit. Do not reuse the Windows administration password. The bridge owns token lifetime until that one session closes; subsequent authentication of the same token is refused. Configuration parsing and TCP envelopes use allocation-bounded Zig, native Winsock/listener ownership uses documented C.

Bootstrap framing is little-endian and byte-defined, never a native struct. ClientHello is128bytes:0..7 ASCII WDTCP001,8..11u32version1,12..15u32extent128,16..47 token32rawbytes,48..63 nonce16raw random bytes,64..127 zero. Read exactly128 under one5-second whole deadline; reject malformed/nonzero reserved before receiver creation. Compare all32tokenbytes without early exit; reject/close on mismatch and never emit token diagnostics. Consume the token on successful authentication. ServerHello is224bytes:0..7 WDTCP001,8..11u32version1,12..15u32extent224,16..23 nonzero randomu64sessionidentity,24..39 exact clientnonce echo,40..63zero,64..223 the actual160-byte negotiated receiver capabilities packet. Decode with the existing capset codec and require compatibility. Client then sends the existing exact160-byte GuestProfile; host compares it to the compiled profile used for its already-negotiated receiver. HostAck is32bytes:0..7 WDTCP001,8..11u32version1,12..15u32extent32,16..23 sessionidentity,24..31zero. Failed authentication/profile negotiation closes without a success acknowledgment or ICD binding.

After handshake, each operation is the existing exact64-byte VenusRequestHeader followed by exactly payload_bytes immutable bytes. Header uses existing magic0x57565131/version1, codecs and reserved-zero rules. Guest callback receives a sequence-zero native venus_request_t and uses the existing encoder after assigning one monotonically increasing nonzero session sequence. One outstanding exchange is allowed. A copied request/header/payload remains callback-owned until completion; no native pointer, handle, file descriptor or padding crosses TCP. Request kinds admitted are2Submit,3Reply,4Create,5Free,6Read,7Write,8Poll,9GpuFence,10GpuPoll. Capabilities/negotiation cannot be replayed after bootstrap. Present12/PresentPoll13 require a future separately implemented Win32 WSI/presentation contract and are rejected here; this initial bridge establishes genuine Vulkan shader work only and cannot establish DXVK Present acceptance.

Owner ceilings: Submit payload8..65620bytes divisible by4; reply payload at most4096; Read/Write payload/range at most4096. Zero-output operations require zero response payload. Existing resource ID2..65, per-resource size/quota, flags/blob/range validation and actual underlying receiver limits remain authoritative. Host bridge validates header before receiving payload and refuses any count above its fixed buffer before copy/allocation. It clears outer sequence to0 only when passing the validated request to venus_guest_exchange, whose internal ring sequence is independently owned. It returns the receiver response/status/payload unchanged apart from restoring the outer request sequence. Native callback sees the same response status and exact payload it would receive via the ring. No synthetic successful result or query cache is permitted.

Response direction is1 with exact matching kind/outersequence, validated stable status0..7 and operation-specific payload. A valid operation-error envelope has no payload and remains an ordinary operation result. A partial header, partial payload, EOF, mismatched identity/sequence/kind, nonzero reserved bytes, over-ceiling extent, native socket failure, canceled call or elapsed deadline makes the session permanently unusable, closes both directions and maps to the existing terminal Ring status; output payload remains unchanged on failure. Sequence maxUINT64 cannot wrap: it closes after the final permitted sequence. RequestAgain means an acknowledged operation retry with a new sequence, never replayed old bytes.

Every exchange uses one monotonic whole deadline including header, payload and response; short read/write, EINTR/WSAEINTR and would-block retries do not extend it. Cancellation is an atomic release-set flag checked before every retry and wait. Guest callback is serialized by the ICD process mutex, never reenters the ICD and retains no call-scoped input/output pointer after return. Socket event/state owner is single-threaded; stop first prevents new application calls and interrupts pending I/O, then joins the bridge owner before closing/freeing callback state. Normal stop requires all Vulkan objects destroyed and venus_icd_unbind RingOk before releasing the frontend. Poisoned/aborted stop retires the host receiver session and stops/reaps the isolated worker before venus_icd_abandon; only then free callback buffers/socket/event and FreeLibrary. WinRM is administration only, never a per-command fake Vulkan responder.

Required tests before code credit: independent literal handshake/envelope oracle; every truncated header/reserved/sequence/count boundary; unauthorized token and profile mismatch with no worker leak; partial payload/response/disconnect/cancel/deadline fault injection; sequence exhaustion; repeated init/bind/object destroy/unbind/stop with zerohandles/FDs; actual cross-VM physical storage shader64word proof and copied push proof after RequestWrite/GPUdispatch/RequestRead; ASan/LSan/UBSan on host native ownership, Zig testing allocator zero leaks, at least90%protocol/memory branches. Run Windows native callback/codec tests and actual medium-integrity private-loader discovery. Later Vulkan1.3/extensions and Win32WSI are explicit additional milestones, never inferred from bridge or triangle success.


## Implementation files and concrete public ABI

The bounded parsing/codec boundary is include/waddle/venus_tcp.h and src/vgpu/venus_tcp_wire.zig. The header includes only portable request/capabilities types and standard integer/size/atomic definitions. No native Winsock headers or native socket structs are exposed. venus_tcp_socket.c is the sole Winsock/POSIX socket lifetime/deadline abstraction; venus_tcp_client.c owns sequential callback framing, venus_tcp_server.c owns authentication and one validated actual guest-forwarding session. tcp_bridge_main.c owns Linux listener/config/real receiver controller resources. tcp_bootstrap_windows.c owns explicit DLL startup/teardown, and its .def lists only documented snake_case start/stop/session/abandon APIs. This is an explicit controlled test bootstrap module, not a graphics driver or implicit loader-lock initializer. Tests and scripts/vgpu_tcp.mk own all independent build/verification artifacts; root may add the GNUmakefile include after gates pass. README, existing ICD source, main vgpu.mk and shared coverage framework are outside these files' edit ownership.

Native caller-owned config record fields, in order: u32version, u32port, u32exchange_timeout_ms, charhost[16], u8token[32], charicd_path[1024]. JSON input has exactly six keys: version integer1; host one of the two address literals; port integer1..65535; exchange_timeout_ms integer1..60000; token64 lowercase ASCIIhex; icd_path ASCII absolute drive-root or UNC path1..1023bytes. Reject embeddedNUL and allnon-ASCII input; reject missing, duplicate or additional keys. Paths and strings are copied into the native record before parser storage expires. Config failure zeros the entire decoded output. Parser JSON DOM allocations use a private fixed65536-byte scratch allocator, then release/reset all scratch within that call; oversized node structure returns Limit, never unbounded malloc. The caller owns and explicitly scrubs token/config bytes after session teardown. No function logs or returns the token as a diagnostic string.

Pure wire exports encode/decode ClientHello(token32/nonce16), ServerHello(sessionid/nonce16/capset160), Ack(sessionid32bytepacket), and validate admitted request ceilings/response pairing. Encode inputs are nonnull immutable accessible fixed extents, borrowed only for call and disjoint from output; output length must equal the exact packet extent. Invalid encode leaves output unchanged. Decode input is private immutable bytes with exact packet length; outputs are disjoint fixed records and zeroed on failure. Return values are existing RingOk/Invalid/Corrupt/Limit, with no dynamic ownership. Magic/version/size/reserved fields are all checked before any copied nonce/token/capset can escape to native C. ServerHello capset bytes are subsequently decoded and checked with the existing capabilities codec/compatibility owner; no new implementation duplicates the authoritative capset validator. Token comparison loops over all32bytes before deciding success. Request envelope encode/decode reuses the existing venus_request ABI and literal64-byte serializer; the TCP profile adds the stricter admitted-kind and command/reply/read/write ceilings only after envelope validation. RequestReply range argument_one must be1..4096 as well as response<=4096; RequestRead/Write ranges are1..4096; unsupported kind is Invalid locally and Corrupt remotely.

Socket record is caller-owned zero-initialized storage holding a native intptr_t socket identity, explicit initialized Boolean, and on Windows only the owned WSAStartup reference. Successful initialization transfers that one socket to the record; failed initialization closes any native socket already acquired and balances Winsock. Close is nullable/idempotent and clears native identity before close to prevent double-close. Deadline read/write take borrowed disjoint private byte spans, cancellation pointer and one absolute monotonic u64deadline; the entire operation uses that deadline without reset. Linux uses nonblocking sockets with CLOEXEC and poll; Windows uses nonblocking Winsock sockets and select/WSAPoll, no borrowed overlapped HANDLE masquerading as a Winsock socket. Wait slices are at most10ms so cancellation is bounded independently of ordinary timeout. recv0 before any expected bytes is Closed; recv0 after a partial record is Corrupt. Native I/O owns no heap or caller buffer after return.

Client record owns socket, next_sequence, authenticated sessionidentity, timeout, sticky terminal status, and fixed65620-byte request/4096-byte response staging. Caller initializes a zero record; client_init connects/authenticates/validates capset/profile/Ack before publishing ready state. client_exchange has the exact venus_command_exchange_t signature and borrows request/input/output only through return. It validates local request and capacities before any publication, copies caller payload to private staging, encodes a header with next_sequence and transmits it. It receives/validates complete response into private staging before copying output or publishing native response. Application input/output may alias each other but not record/scratch/header; ordinary operation status follows the existing guest_exchange mapping. All terminal transport/protocol/deadline/cancel outcomes remain sticky and forbid further wire calls. Client_free is idempotent after callbacks stop; it closes the socket and scrubs all staging/config/counters. Client APIs are externally serialized, no hidden worker thread or independent heap allocator.

Server owner stores accepted socket, outer expected_sequence, sessionidentity, timeout and fixed65620/4096 staging. Authentication validates ClientHello before the real controller/worker is created. After worker initialization and actual venus_guest_init, server sends that receiver's capabilities, validates the exact compiled160-byte GuestProfile, and emits Ack. The profile is exactly the existing GuestProfile declaration: every byte is0 except indices0=1,4=0x33,5=0x41,6=0x40,8=1,12=3,16=1,20=1,68=3,152=1. A compile/test comparison with independent fixture bytes prevents accidental divergence. The controller captures the exact160-byte actual RequestCapabilities reply once through the live unnegotiated RPC before calling venus_guest_init (which independently repeats capability discovery and performs negotiation). Decode/compatibility checks apply to both; require byte-identical decoded160-byte snapshots before sending the captured actual wire bytes. There is no capability encoder export and no reconstructed query reply; this extra real query retains authoritative bytes. After handshake server forwards through the borrowed live venus_guest_t only, never fabricated callback values. A delivered ordinary receiver operation error is returned as its exact envelope; an underlying terminal zero-response failure closes the transport.

## Stop, cancellation and receiver retirement

Normal stop first requires all application Vulkan objects destroyed and venus_icd_unbind returning RingOk. Guest write-half-closes its authenticated connection. A server that sees EOF before any new64-byte request header treats this as an orderly stop, stops/retire/reaps its owned actual receiver worker and frees guest/RPC/channel/mapping in that order, then sends a32-byte retirement Ack with the same established sessionidentity, and finally closes TCP. The guest validates that exact Ack before releasing callback/context/socket and ICD HMODULE. No object is credited as retired merely because a GPU fence retired or a socket closed. A partial header EOF is malformed; no successful normal retirement Ack is emitted before teardown.

Terminal transport loss cannot prove receiver retirement in-band. Bootstrap stop returns Again/terminal status while retaining live bound context if ordinary unbind cannot succeed. The trusted test launcher supervises the host bridge result/exit and confirms that the exact authenticated session's receiver worker was stopped and reaped. Only then it may call bootstrap_abandon(retired_session_id), which requires the nonzero matching sessionidentity and explicitly invokes venus_icd_abandon before client/module/config teardown. The supplied identity is a trusted supervisor assertion, not proof derived from an untrusted guest packet; the API documents this precondition. Test error/cancel/disconnect orchestration must wait for and assert host retirement before invoking it. If the worker cannot be reaped within the configured bounded shutdown, host retains its ownership/result as a failure, and guest must not fake successful abandonment. Caller must prevent new Vulkan calls and wait existing callbacks before either teardown API; this controlled module does not introduce hidden threads or promise concurrent start/stop.

Host native controller uses a new private memfd-backed region and socketpair, not any user disk or AV mapping. Controller initializes region/session, launches the existing isolated worker with its inherited mapping/control descriptors, completes existing Offer/Ack/Ready and negotiated frontend, then authenticates application traffic as above. Every failure site has reverse teardown: stop/reap child first; free guest/RPC/channel/session views; unmap mapping; close both retained control endpoints and mapping FD; scrub token/buffers; close accepted socket/listener. Regular config file access is bounded; host rejects nonregular files and group/other permissions for token-bearing config. Ready/result files contain only localhostport, authenticatedsessionidentity, source/runtime verdicts and worker-retirement status, never token/credentials. They are created privately by the launcher. The host listener accepts exactly one configured launch session; malformed or unauthenticated first connection exits failure without any receiver child. No retries silently create extra receiver namespaces.

Build gates separately verify pure codec/config coverage and independent C literal packets, portable native socket/client/server fault fixtures, actual host worker integration, and Windows DLL/client crossbuild/native VM execution. Each fixture destroys owners in normal and failed acquisition/partial-I/O/cancel paths and proves descriptor/handle baselines under ASan/LSan/UBSan. Distinct code/test/doc increments are atomic commits, with task#11 progress credited only by root's synchronized tracker once that increment's gates pass. Presentation/DXVK modern feature work is expressly outside this first bootstrap profile.

## Native socket ownership and Windows handle verification refinement

The portable socket record is `uintptr_t handle` and `uint32_t initialized`; no native platform structure or owning thread is exposed. The socket-only abstraction returns `RingClosed` and the exact received byte count on EOF, including partial EOF; the client/server framing owner then classifies nonzero partial-header/payload count as protocol corruption. Windows waits use `select` read/write and exception sets, while Linux uses `poll`; every wait slice is at most10ms and every retry retains its original absolute deadline. A failed connect must release its staged socket and Winsock reference before returning. A refused Windows loopback connection can take more than1s while the native network stack retries; the refused-connection regression gives the OS5s while the independently tested send/receive/cancel deadlines remain20ms/1000ms. This does not extend any production exchange deadline.

Windows11 build26300.9457 native handle snapshots exposed a transient unnamed system Event after otherwise complete socket cleanup. An ignored diagnostic inspected `NtQueryInformationProcess(ProcessHandleInformation)` and calibrated `CreateEvent` as object type index21 with access0x1f0003. Eight repeated actual loopback lifetimes produced81→82→81 counts; the added Event usually retired before immediate `NtQueryObject` or `DuplicateHandle` (invalid-handle result), and one successful temporary duplicate explicitly identified type`Event`, empty name, access0x1f0003. The diagnostic duplicate was closed synchronously. After1s the process returned to81 handles. This is empirical evidence for independent OS Event retirement, not permission to retain a project socket, thread, event or Winsock reference. The production abstraction allocates no Event or owning thread. Microsoft documents Winsock teardown and socket closure in https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-wsacleanup; that documentation supplies no universal1s guarantee, so the bounded native regression treats deadline exhaustion as failure.

The native socket test first warms the complete socket/CSPRNG paths and allows at most1s of OS quiescence before recording its baseline. After every subsequent fully torn-down lifetime, Windows must independently prove that raw `socket(AF_INET,SOCK_STREAM,IPPROTO_TCP)` fails with `WSANOTINITIALISED`, establishing that all project `WSAStartup` references were released. All project owners are zero and their sockets are synchronously closed before this check. The test then allows at most1s for an independently retiring OS Event to disappear, polling at1ms and requiring the **exact** baseline process handle count. Any remaining extra handle or deadline exhaustion fails the test; no count tolerance, suppression, retained initialization reference or disabled leak checker is permitted. Linux requires immediate exact `/proc/self/fd` baseline equality. Native allocation/error/cancellation tests continue to run with ASan/LSan/UBSan and their normal zero-leak requirement.

The eventual explicit Windows bootstrap resolves the additive `venus_icd_bind_capabilities(exchange, context, capabilities)` interface specified by shared contract commit`ba0983c`. It passes the copied, authenticated, authoritative host capability snapshot from the actual server hello after existing capability decode/compatibility checks. It must never use the legacy callback-only bind to synthesize newer device capabilities. This refinement changes no advertised Vulkan version, extension, WSI support or DXVK completion claim.

## Sequential client and server public interface contract

`venus_tcp_client_t` is a caller-owned noncopyable sole-thread record with one portable socket, nonzero authenticated session identity, next outer sequence beginning1, immutable1..60000ms exchange timeout, sticky terminal status, copied decoded160-byte authoritative capabilities and fixed65620-byte transmit/4096-byte receive arrays. Zero-init before `venus_tcp_client_init`; init borrows the validated configuration and optional release-set cancellation flag for that call only, uses one5s handshake deadline, generates a16-byte nonce using the system CSPRNG, publishes no live owner until complete matching hello/capset/profile/Ack validation, and scrubs private staged handshake bytes on every path. It retains no pointer into config or handshake scratch. Capability decode and pinned compatibility are mandatory before publishing. Wrong echoed nonce, zero session, unsupported capset, truncated packet or invalid acknowledgment closes staged ownership and leaves the caller record zero.

`venus_tcp_client_exchange` has the exact existing `venus_command_exchange_t` ABI. It validates the sequence-zero local request through existing request encoding with the next nonzero outer sequence, then stricter TCP admission. Payload length must equal the request declaration; successful Reply/Read output capacity must cover its exact requested byte count and be at most4096; every other admitted operation has no response payload capacity. Input and output may alias one another, but neither may overlap the client record, request or decoded response; the decoded request and response cannot alias each other or the owner. Invalid local arguments return before network publication and preserve the usable owner; valid disjoint response storage is zeroed on all failed exchanges. Complete request payload is copied to owned staging before any send. All network stages share one whole exchange deadline. Response kind/direction/outersequence/status/operation shape and ceiling are validated using the existing envelope codec and TCP guard before output bytes or decoded response are published. Wire status is translated to the exact existing Ring status. An ordinary delivered Again/Invalid/Limit retains the usable transport and advances the sequence, while an acknowledged Corrupt/Closed/Cancelled/Timeout, any I/O/protocol failure or outer sequence exhaustion closes the socket and records sticky loss. The last allowed outer sequence is UINT64_MAX-1; UINT64_MAX is reserved as exhausted and never published, so no counter can wrap or silently reopen a session.

`venus_tcp_client_retire` may run only after application calls stop and the ICD successfully unbinds. It half-closes writes, reads/validates the established-session retirement Ack under one configured deadline, then closes the socket and marks the transport retired while preserving its session identity for the caller's supervisor accounting. Success is the host's explicit confirmation that the actual worker was already stopped/reaped and local controller storage released. Failure closes the socket and stays terminal without claiming retirement. `venus_tcp_client_free` is nullable/idempotent and scrubs the entire owner; callers must first satisfy the unbind/retirement or trusted externally verified host-retirement/abandon precondition before freeing a bound callback owner. The optional cancellation pointer is borrowed only by the active call, not retained; the Windows bootstrap passes its owned stable flag from its serialized lifecycle.

`venus_tcp_server_t` owns an accepted socket (moved from the caller only on successful authentication), authenticated nonzero session identity, expected sequence1, configured deadline, sticky status and the same fixed staging extents. `venus_tcp_server_authenticate` receives/validates the exact client hello and timing-safe token before any renderer worker is created. It generates a nonzero64-bit session identity from the CSPRNG, copies the nonce, and records the original5s handshake deadline for continuation. A rejected client consumes/closes the accepted connection with no worker creation. After actual controller startup and raw capability capture/negotiation, `venus_tcp_server_negotiate` borrows the real `venus_guest_t`, verifies supplied raw160-bytecapset equals its authoritative decoded capabilities, sends the actual hello, validates the exact compiled guest profile and sends session Ack under that same handshake deadline.

`venus_tcp_server_step` processes at most one header/payload exchange through the borrowed live guest frontend. It validates exact expected outer sequence, existing operation rules and stricter admission before dispatch. It strips only the outer sequence to zero for the existing guest call and publishes the actual validated receiver response with the outer identity restored. CPU/GPU IDs, resource IDs, statuses and actual payload bytes are not reconstructed or fabricated. Deadline remaining is passed to the real guest exchange, so receiver processing and response I/O share the original configured whole budget. If receiver failure returns no complete decoded response, close the transport; never manufacture an error response. Success step returns RingOk even for ordinary delivered operation-error envelopes because that indicates one framed exchange was completed. Clean EOF before a new header returns RingClosed without closing the accepted socket, allowing controller retirement before acknowledgment; partial EOF or other terminal failure closes and remains sticky. A separate `venus_tcp_server_ack_retired` has the explicit caller precondition that the exact controller worker was already stopped/reaped and guest/channel/mapping storage released; only then it sends Ack and closes the socket. `venus_tcp_server_free` closes and scrubs but never pretends that a worker was retired, and never owns the externally borrowed actual guest/controller. No client/server function creates a hidden thread or allocates dynamic memory.
