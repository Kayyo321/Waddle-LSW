# Pending native acceptance: isolated Windows desktop and Wayland

Status: not executed in the implementation container. It has no interactive Windows desktop, Wayland compositor, KVMFR or IVSHMEM device. API doubles, codec/state tests and cross-links are separate evidence and do not qualify physical injection, UIPI behavior, compositor scheduling or application delivery.

## Safety and collection

Use a disposable, isolated interactive guest desktop and the already-authorized AV installation. Do not run these traces on a desktop containing unrelated work or sensitive applications. `SendInput` is desktop-global. Foreground checks and observed transitions do not provide an atomic target-delivery guarantee. Record the exact source commit, Windows/compositor versions, process integrity levels, host/guest logs and fixture receipt log. Stop immediately if any unexpected application receives input.

Run `av_windows_test.exe --lease-fixture` in the guest. It creates ordinary ownerless windows A and B, a tool window and an owned APPWINDOW rejection target, and prints their PID/HWND identities. It logs timestamped focus, physical key, button, wheel and close message receipts. It synthesizes no input and remains open until A and B close. Start `waddle-guest-av.exe PROCESS_ID` for the printed PID through the existing authorized managed AV path; start `waddle-av-host GUEST_CID SHARED_MEMORY_PATH` on the Wayland host with that session's verified CID/mapping. No desktop switching, credentials, driver setup or new permissions are part of this trace.

Capture control traffic only with the project's existing trusted debugging facilities or a debugger attached with separate authorization. Decode the 328-byte frames using the checked-in protocol offsets: incarnation at 48, epoch at 56, serial at 44. Diagnostic logs themselves are not authoritative proof that every OS hook notification arrived.

## Required traces and expected observations

1. Startup unarmed: launch while the guest shell or tool window is foreground. Confirm CreateV3 precedes Revoked epoch 1; barrier Ack precedes Ready. Before a fresh post-Ready host keyboard enter, no forwarded key/button/pointer/wheel event may be inserted. Initial enumeration must not activate A or B. Leave and freshly enter A on the host; Focus-on must complete validation before following data.
2. Same-process recovery: hold a supported key and button in A, then make already-exported B foreground in the guest. Confirm releases of all inserted holds before Revoked epoch 2. Complete the barrier/Ack/Ready sequence. Ready alone must not activate or move anything. Freshly leave/re-enter the host surface and pointer, then confirm new input works once on the chosen live ordinary target.
3. Same-HWND stale input: retain the original live A HWND/incarnation through recovery. Old-epoch Focus/key/button frames, even for that exact pair, must produce no native effect; their serials are still consumed. A later fresh current-epoch focus may use A. Do not interpret handle equality as epoch authorization.
4. Observed A→B→A before the first revocation's Ack: session must terminate disarmed. It must not coalesce the intermediate observation or restore the previous focus because actual foreground returned.
5. Suppression: hold a key across revocation; down/up callbacks while blocked must update local bookkeeping only. An authoritative keyboard-enter snapshot that omits the key clears stale suppression. Present held keys stay suppressed until release. A button held across off-surface changes may conservatively swallow the first complete click if its release was unseen; later ordinary clicks must work.
6. First fresh click/scroll: after fresh post-Ready pointer enter and keyboard focus, click without requiring another motion. Confirm a current-route PointerV3 precedes ButtonV3. Repeat for wheel. The fixture must log the event only for the intended active test window; this observed result is a test outcome, not a general SendInput guarantee. Button-up outside bounds and pointer-leave cleanup must not leave held buttons.
7. Rejections after anchoring: separately foreground the visible tool, owned APPWINDOW, an unrelated process, or an unavailable receiving-input desktop under authorized test conditions. Each must terminate/disarm; no automatic recovery/admission of those targets. Run each in a new session after successful teardown. Preserve the existing `av_windows_test.exe --input` unrelated-foreground terminal test independently for V2.
8. Anchor destruction: with A anchored, destroy A while B is current and already exported. Recovery may target B through a new epoch. With no eligible exported replacement, terminate. A recreated HWND must use a new incarnation and cannot inherit routes or held state.
9. Timeout and disconnect: with an authorized debugger/test transport, delay Ack/Ready beyond the fixed two-second monotonic deadline, including while other traffic continues. Late matching traffic must not rescue the handshake. Disconnect with held input; bounded cleanup must release successful holds and stop publication. A separately started fresh connection must repeat capability selection and the full barrier sequence with empty state.
10. UIPI and ambiguous insertion: separately verify the documented failure behavior when native activation or insertion is refused. No retry/replay of ordinary input is allowed. Horizontal wheel already inserted followed by vertical failure is terminal and is not replayed as a whole wheel operation.

## Acceptance record

For every trace record pass/fail, exact traffic order, fixture receipt times, foreground observations and cleanup outcome. Missing evidence remains pending. Silent OS notification loss, wholly unobserved leave-and-return, concurrent unrelated guest input, stalled synchronous native calls, and same-process HWND reuse without observed lifecycle evidence remain unqualified even after successful traces.
